# Host "Cancel event" + apology email draft; "Guest asked to cancel" removed (2026-10-05)

## Status: PARTIALLY WORKING (web + iOS built and compiling; migration 141 NOT applied remotely; nothing exercised against a real event/mail account)

- Individual booking cancel: `guest_requested` ("Guest asked to cancel") removed from `CANCEL_BOOKING_REASONS` (`GocContext.jsx`) and `ReasonOption.cancelBooking` (`AppState.swift`). Server never validated the key; old bookings that already carry it are unaffected.
- Guest check-in screen (`Attendance.jsx` / `AttendanceView.swift`) has a "Cancel event" action → `CancelEventModal.jsx` / `CancelEventSheet.swift`, two phases:
  1. **plan** — pick one of 4 apology templates (unforeseen / venue / low sign-ups / safety, vi+en, in `src/lib/eventCancellationTemplates.js` and `Lib/EventCancellationTemplates.swift` — keep in step), preview, confirm → existing `cancel_event` RPC (cancels bookings, opens refund claims, posts thread message).
  2. **send** — one personalised draft PER ticket holder, each opened in the HOST'S OWN mail app (`mailto:` on web; `MFMailComposeViewController` on iOS, `mailto:` fallback when no Mail account). banbe sends nothing: the host presses Send from their own mailbox (server-side sending is reserved for the planned "Plus" plan). Each guest sees only their own address. A secondary "one email to everyone (BCC)" link remains for convenience.
- Placeholders: `{{guest_name}} {{event_name}} {{event_date}} {{event_place}} {{organizer_name}}`. `{{guest_name}}` is the guest's own name in an individual email (falls back to "there"/"bạn"); in the BCC draft it is everyone's names, shortened past 6.
- A cancelled event opens straight into **send** ("Email ticket holders" on the cancelled-event screen), so the host can leave and come back. Which guests were already drafted is remembered per event on this device (localStorage / UserDefaults); the app can't know a mailto draft was actually sent, so "Drafted ✓" means "opened", not "sent".
- Emails come from `get_event_ticket_holders(p_event)` (migration 141, SECURITY DEFINER, organizer/admin only, read-only): confirmed + live pending bookings, and — once the event is cancelled — the bookings `cancel_event` stamped with the event's own `cancelled_at`; a gift's recipient AND purchaser; de-duped by email. **Must be applied with `supabase db push`** (141 was edited in place before it was ever applied); without it the sheet shows "couldn't load the ticket holders".
- Not done: no in-app notification beyond the existing thread system message; refund wording in templates assumes the host refunds in full; draft state does not sync across devices.
