# 45 — iOS: native glass everywhere, Home title, Schedule month view/logo/swipe zones, Account tabs, swipe stutter (2026-10-17)

Status: IMPLEMENTED LOCALLY (iOS only), NOT committed/pushed. No DB/RPC/migration/web change. Follow-up to the on-device review of note 44 (commit 0d6bc88 is note 43; note 44 work is uncommitted).

## 1. Swipe stutter — what was found and changed (NOT verified on a device)
No profiler was available; these are causes found by reading the code, all fixed:
- `ActivationChecklistCard` (Home, note 43) called LocalAuthentication `canEvaluatePolicy` 4–8× on EVERY Home body pass. `AppState.now` is republished every second and every `@EnvironmentObject app` view re-evaluates, so Home paid a synchronous system call per second (and while mounted as a swipe neighbor). Now: `BiometricAuthService.cachedAvailability` (re-read on `didBecomeActive`) and an early exit when the checklist is off/dismissed.
- `ScheduleView` recomputed its derived data ~15× per body pass (every card/strip dot read `app.mySchedule`/`scheduleDiscover`, each rebuilding from 300 discovery events). Now one memoized `ScheduleSnapshot` (`app.scheduleSnapshot`, cache key = hash of the inputs + 30 s bucket), read once per body (`ScheduleView` → `ScheduleScreen(snap:)`).
- Schedule was mounted as a swipe neighbor and its `.task` loaded bookings/events immediately — a load republishes app-wide state mid-drag. Now the load is deferred 450 ms (a cancelled swipe cancels the task) and throttled to once per 45 s (`force` on pull-to-refresh).
- Schedule cards used plain `Button`s; now `SwipeSafeButton` like Home/Account, so a swipe that starts on a card is a swipe.
Measured only: cached snapshot read with 300 events < 20 ms (unit test). Whether the on-device feel is fixed needs the owner's confirmation.

## 2. Home header
"Home" never drops. `headerTopRow` is a `ViewThatFits` over: wordmark 112/title 27/controls 52 → 96/27/46 → 80/24/46 → 70/22/44 → 58/22/44 → (last resort) no wordmark, title kept. On the widest phones (≈440pt) the logo, Home, streak/coins, bell and search all fit; the narrowest phone (390pt) uses the 58pt wordmark. Ids: `home.title`.

## 3. Schedule
- Header now has the banbe wordmark before the title (same pairing as Home/Notifications).
- **Month view** (`ScheduleMonthSheet`, opened from the month button, replaces the graphical DatePicker "pick a date" sheet): month grid by whole weeks (locale first weekday), up to three dots per day from real events of the current mode, selected week highlighted, month nav, the month's agenda below grouped by day. Tapping a day, week row cell or agenda item selects it and returns to the week view on that week. Pure logic in `SchedulePresentation` (`monthGrid`, `dayCounts`, `monthAgenda`, `monthStart`, `addMonths`) with tests. It shows My schedule or Discover (picker inside the sheet).
- **Dock hides while the sheet is open**: `BottomTabBarOverlay.setSheetOpen(id,_)` (set of open sheet ids, any → hidden) via `.hidesDock("schedule.month")` on the sheet content. Reusable for other sheets that cover the dock. Verified on the real RootView (the dock window's `tab.*` elements disappear and return).
- **Swipe zones**: the mode picker + week strip are a root-swipe exclusion zone (`.rootSwipeExclusion`, the same `rootGestureExclusionZones` mechanism Home's filter strips use) and a swipe on the strip changes the WEEK (±7 days). They sit in a fixed header above the scroll so the zone doesn't move (a zone inside scrolling content would republish every frame). At accessibility text sizes the header scrolls with the content and the zone is off. Swipes over the agenda still switch dock sections (tested both ways). Interpretation: the "tab bar" in the request was read as the week strip / mode control, not the dock itself (whose scrub gesture is intentional).

## 4. Account tabs
Personal / Host / Admin are now one full-width 52pt segmented control (icon + label + badge, sliding ink indicator, native glass track; stacked 56pt rows at accessibility sizes; text capped at accessibility1). Swipe left/right anywhere on the Account column (header, tab strip or content) changes tab; no wrap-around and it never hops to another dock section: while there is more than one tab the whole screen is a root-swipe exclusion zone (`account.tabs`). With only Personal there is nothing to swipe between, so the dock swipe stays. Taps, badges (`account.tab.<key>.badge`) and ids unchanged. Known limitation: a synthetic XCUITest drag that STARTS on a row can activate the row (the repo's old tests avoid rows for the same reason); the swipe tests start in the header.

## 5. Native glass everywhere
- New `Views/NativeGlass.swift`: `nativeGlass(_:interactive:tint:fallback:)`, `nativeGlassCapsule`, `nativeGlassPanel`. iOS 26+: Apple's `glassEffect` (follows Settings > Display & Brightness > Liquid Glass and Reduce Transparency); earlier iOS: the matching system `Material`. A selected chip is the same glass tinted with ink.
- Removed: `AppState.glassOpacity`, the Preferences "Liquid Glass" slider/preview (replaced by a one-line note pointing to iOS Settings), `homeGlassCapsule`'s opacity/fill maths, `accountGlassCapsule`, the glass panel's `.opacity`, QR scanner/Pulse panel opacity, the Home area-menu `.id` rebuild hack. The stored `banbe.glassOpacity` value is deleted on launch.
- Converted to the helper: Home header/chips/rewards capsule/search/bell, Account tab track, Schedule Today button, the dock "+" button (it was a plain material beside a glass dock), Map close/compass/search-here/chips, `glassPanel()` (area pickers), QR controls, Pulse panel. Left as they were (already native or not glass buttons): the dock itself, liquid toggle knob, Host setup close, Admin test switches, text-heavy Map cards, the pre-iOS-26 fallback close buttons.

## Note 46 follow-up — Event Detail calendar button (2026-10-18)
The two big "Add to banbe Schedule" / "Add to Apple Calendar" buttons are replaced by `EventPlanTitleRow` (Views/EventPlanActions.swift): ONE small native-glass button at the title's trailing edge with a status label under it — "Discover" (not in the schedule), "Added" (in banbe Schedule, check icon), and once the event was also saved to Apple Calendar two connected glass segments (banbe + Apple). Tapping opens a native `Menu` whose items depend on state (Add to banbe Schedule / In My schedule · source / Remove [manual adds only] / Add to Apple Calendar [again] / Clear Apple Calendar mark). Results show as a short line under the title (fades after 6 s).
- New `AppleCalendarMarkStore` (UserDefaults `banbe.schedule.appleCal.v1.<uid>`, event keys only). The system editor runs out of process with no permission, so the app only knows Save was pressed, not a later deletion in Calendar — hence the "Clear mark" menu item.
- Ids: `event.plan.button` (+ menu items `event.schedule.add|remove|inMine`, `event.appleCalendar`, `event.appleCalendar.clear`, `event.plan.message`). UI tests updated (menu opened first).
