## How the switch works
One shared rule, `src/lib/contentFlags.js` ⇄ `Lib/ContentFlags.swift`, built on the platform flags:
`rewards` (Rewards on; missing key = on, like the app), `rewards_daily` (Rewards on, v2 off) and `rewards_v2`
(both on). The daily/weekly split keeps the text true to what the app shows: production has `rewards_v2` OFF, so the
guide describes the daily streak, and weekly streak/grace/repair/tiers/goal text appears only with v2.
Markers: help section `flag:`, block `['flag', key, block]`, list item third element; policy `on(key)` guards and
`{ flag, cells }` table rows. Filtering happens BEFORE the reader builds its table of contents and search, so with
Rewards OFF there is no Rewards section, TOC entry, search hit or Q&A item. Turning the switch on shows them on the
next flags read (start, foreground, sign-in), no release. The public `/privacy` page reads `get_feature_flags`
itself and shows no switched text until it has an answer (no flash).
