# banbe — project context

banbe is an event/ticketing app: React 19 + Vite web app (`src/`), SwiftUI iOS app (`apps/ios/`, generated by XcodeGen),
Supabase backend (`supabase/migrations/`), Vercel functions (`api/`). Read `CLAUDE.md` first — it indexes 101 numbered
notes in `.claude/notes/` that are the system of record for behaviour.

## Commands

```bash
npm run build        # the check that must pass for any web change
npm run test:unit    # node --test tests/unit/**/*.test.mjs
npx playwright test tests/public/<spec>.spec.js   # focused browser spec
npm run dev          # Vite dev server
cd apps/ios && xcodegen generate                  # after pulling iOS changes
```

## Finish line

State it honestly: built / unit-tested / focused spec / iOS compiled / device-checked are five different claims. If
you did not look at a visual change, say "not visually checked".

## Guardrails

- **Money and refunds:** read `.claude/notes/02-confirm-qr.md` and `16-refund-lifecycle.md` before changing anything that
  confirms a payment or moves money. `verify_payment` is organizer-only since migration 213.
- **Deletion:** a plain `DELETE` on an event cascades away payments, refunds and disputes. Removal is a status; read
  `.claude/notes/54-admin-event-removal.md`.
- **Migrations:** always a new numbered file in `supabase/migrations/`; never edit an applied one. Apply with
  `supabase db push` and record the date. Do not claim applied without a log line.
- **Feature flags:** a missing flag means ON; seeded values live in `app_feature_flag_defs`.
- **Web Baseline floor is Safari 16.2 / iOS 16.2.** Check `.claude/notes/90-modern-web-guidance-pass.md` before adding a
  platform feature; a newer-than-floor API needs a fallback or it waits.
- **Read-only by default for audits.** Do not commit, push, deploy, or run migrations unless explicitly asked.
